# Автоматическая отправка офлайн-прослушиваний

## Цель

Прослушивания скачанных треков в Finamp должны автоматически появляться в Jellyfin Playback Reporting после восстановления доступа к домашнему серверу. Сохранять исходное время и реально прослушанную длительность. Не требовать Last.fm/ListenBrainz и ручного экспорта.

## Исходное состояние

- Основа ветки: Finamp 1.0.1, commit 65c1a78b1d04dd8525825ecdf2cf39c7442b51e9.
- Локальная установка: Jellyfin 10.11.11, Playback Reporting 17.0.0.0.
- OfflineListenLogHelper пишет Hive OfflineListens и listens.json. Автоматического отправителя нет.
- Текущая запись содержит время остановки и идентификаторы, но не реальную длительность прослушивания. Нельзя достоверно восстановить длительность старых записей по длине трека.
- Обычные Sessions/Playing события описывают текущую сессию. Их повторная отправка не является импортом истории с исходной датой.
- Существующий PlaybackReportingActivityController защищён RequiresElevation. Администраторские учётные данные не должны становиться условием работы мобильной очереди.
- Открытый upstream PR https://github.com/jellyfin/jellyfin-plugin-playbackreporting/pull/145 добавляет POST /user_usage_stats/offline_activity, но заявлена проверка на Jellyfin 12. Совместимость с 10.11.11 не подтверждена.

## Предлагаемая реализация

1. Проверить и адаптировать серверный endpoint для 10.11.11: обычная авторизация пользователя, сервер определяет владельца из сессии и проверяет доступ к ItemId. Ограничить размер пачки и проверять временные поля/длительности.
2. Назначать каждому завершённому прослушиванию постоянный event ID. Сервер хранит уникальный ключ (пользователь, устройство, event ID); повторная отправка после потери ответа не создаёт дубль.
3. Хранить устойчивую очередь на устройстве, привязанную к серверу и пользователю. Записывать начало, окончание и фактическое время воспроизведения; не считать паузы и перемотку прослушанными секундами.
4. Отправлять небольшими пачками при возврате доступа к серверу, запуске/возобновлении приложения и периодически, пока приложение работает. Наличие Wi-Fi само по себе не означает доступность Jellyfin.
5. Удалять запись из очереди только после подтверждения сервера. Сетевые ошибки повторять с увеличением задержки; отсутствие API показывать явно и сохранять журнал. Не обещать выполнение при полностью выгруженном Android-приложении.
6. Сохранить экспорт listens.json. Старые записи без длительности не импортировать с выдуманным временем прослушивания; предусмотреть отдельную миграционную политику.

## Проверки перед установкой

- Тесты учёта пауз, перемотки, повторов, завершения и смены трека.
- Очередь сохраняется после перезапуска, не смешивает аккаунты/серверы.
- Потерянный HTTP-ответ и повторная отправка не создают дубль.
- При отсутствии плагина/401/403 история не теряется.
- Интеграционный тест на временной базе Playback Reporting; не засорять настоящую статистику синтетическими записями.
- flutter analyze, релевантные flutter test и сборка APK.
- Пользовательский тест: онлайн-трек; офлайн-трек; восстановление сети; проверка исходной даты, длительности и отсутствия дублей в Jellyfin.

## Правило работы с телефоном

Пользователь просит больше не управлять телефоном через ADB/UI. Давать короткие инструкции для установки и проверок; действия на телефоне выполняет пользователь. Загрузку коллекции пользователь выполняет самостоятельно.

## Статус

Создана ветка и описан протокол. Функция ещё не реализована, APK не собран, сервер и телефон не изменены этой веткой.
